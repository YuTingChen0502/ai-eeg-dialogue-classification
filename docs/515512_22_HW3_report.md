# PART 1 — EEG Brain Signal Classification

## 1. Method

### Task 1 — Within-subject classification

A classical machine-learning pipeline is used because the released training set has only 16 trials, which is far too small to fit a deep neural network without severe overfitting.

Pipeline (per band, per design):

1. **Bandpass filter** with a 4th-order Butterworth implemented as a second-order section (`scipy.signal.butter(..., output='sos')`) and applied with zero-phase `sosfiltfilt`.
2. **Channel-wise log-variance** features. For each trial, after filtering, each of the 45 channels contributes one feature `log(var(channel))`, giving a 45-dimensional vector per trial.
3. **StandardScaler** fit only on the training fold, then applied to the validation/test fold.
4. **Classifier:** `LinearSVC(C=1.0, class_weight='balanced', max_iter=10000, random_state=42)`.

This pipeline is small, deterministic, and robust to the tiny sample size.

### Task 2 — Cross-subject classification

The same family of features is used, but extended into a **multi-band concatenation**:

1. Bandpass filter into 3 bands: 8–13, 13–30, 4–40 Hz.
2. Channel-wise log-variance per band, concatenated → 45 × 3 = 135-dimensional feature vector.
3. StandardScaler fit on training data only.
4. **Classifier:** `LogisticRegression(C=1.0, class_weight='balanced', solver='lbfgs', max_iter=2000)`.
5. **Checkpoint** is a `joblib` pickle containing every parameter needed to reproduce the inference transform: `version`, `feature_type`, `bands`, `sfreq`, `filter_order`, `n_channels`, `n_time_points`, `scaler`, `model`, `classes`, and `train_args`. `inference.py` reconstructs the bandpass filters from this metadata so train-time and inference-time preprocessing always match.

LogisticRegression was used as a stable linear classifier for the multi-subject feature space and supports class_weight='balanced' with minimal dependencies.

## 2. Preprocessing Design

Two designs are compared in Task 1, sharing every step except feature pre-processing:

- **Design A — `A_bandpass_only`:** bandpass → log-variance → StandardScaler → LinearSVC.
- **Design B — `B_zscore_bandpass`:** **per-trial per-channel z-score** → bandpass → log-variance → StandardScaler → LinearSVC.

The intent of Design B is to remove per-trial DC offset and amplitude drift before the variance feature is computed. If trial-to-trial amplitude swings dominate the raw variance, those swings are class-uninformative and should be normalized out.

### Filter-validity note (70–125 Hz band)

With `sfreq = 250 Hz`, the Nyquist frequency is exactly 125 Hz. `scipy.signal.butter` requires cutoffs strictly below Nyquist, so the 70–125 Hz experiment is run with the upper cutoff **internally clamped to 124.875 Hz** (`min(high, nyq * 0.999)`) for filter validity. The nominal band name "70–125 Hz" is preserved everywhere user-facing in the notebook output and in this report. The actual cutoff used and a `clamped_to_nyquist` flag are stored in the results table so the clamping is fully auditable.

For Task 2, all bands (8–13, 13–30, 4–40 Hz) sit comfortably inside Nyquist and no clamping is required.

## 4. Analysis / Discussion

### Task 1

- **Frequency band.** Design A on 70–125 Hz produced the best local CV result. This is somewhat counter-intuitive — motor-execution decoding is more often associated with the alpha/mu (8–13 Hz) and beta (13–30 Hz) bands. With only 4 folds × 4 trials, however, the standard deviation (0.18) is comparable in magnitude to the gap between top configurations. The 70–125 Hz advantage on this small set may partly reflect noise, and it should be revisited with more data before generalizing the claim.
- **Preprocessing design.** Design A (bandpass-only) outperformed Design B (per-trial z-score + bandpass) overall: A wins 3 out of 4 bands. Design B did help on the 8–13 Hz band (0.4063 vs A's 0.2188), where amplitude drift is most likely to dominate the variance feature. On 70–125 Hz the per-trial z-score destroys the very amplitude variation that the high-gamma feature relies on, dropping Macro-F1 from 0.5625 to 0.1250.
- **Why z-score can hurt log-variance.** Log-variance encodes signal power. Per-trial z-scoring forces every channel to unit variance per trial *before* filtering, which removes a sizeable part of the absolute power signal that distinguishes classes. For low-amplitude bands (alpha) it can de-noise; for high-amplitude bands (gamma) it destroys signal.
- **Stability.** Several configurations (designs B@70–125, B@8–13) have std = 0, meaning the model produced the same fold scores across all 4 folds. Combined with the very small per-fold validation size (4 trials), this is more a sign of degenerate prediction than of stability.
- **Filter clamping.** The 70–125 Hz experiment is preserved as required, with the upper cutoff clamped to 124.875 Hz internally (`clamped_to_nyquist=True` in `results_df`). This clamping is a technical adjustment required for filter validity and is documented in the results table.

### Task 2 — cross-subject generalization

- **Why this is harder than Task 1.** Cross-subject EEG suffers a covariate shift: each subject has different scalp anatomy, electrode contact, baseline noise, and physiology, which together change the marginal distribution of the features. A model that fits the training subjects' joint feature distribution may still fail on a held-out subject.
- **What we did to address it.** (1) Multi-band features make the representation less reliant on any single rhythm. (2) `class_weight='balanced'` prevents the linear head from collapsing on the majority class if subject-level class proportions vary. (3) The pipeline is fully reproducible via the joblib checkpoint, including bands/sfreq/filter_order, so the inference path produces the same features as training.
- **What may not transfer from within-subject methods.** Methods that calibrate to a single subject (subject-wise band selection, individualized CSP filters, subject-specific channel re-weighting) typically do well within-subject and can be brittle across subjects. We deliberately avoided per-subject tuning.
- **Local-vs-leaderboard relationship.** Train-set Macro-F1 (0.7457) is an optimistic upper bound. Leave-one-subject-out validation, runnable via `python train.py --validate`, provides a more honest estimate of the public-leaderboard score because it mirrors the deployment setting (held-out unseen subject).

# PART 2 — Dialogue Continuity Classification

## Task setup and metric

Binary classification: `1 = Complete`, `0 = Incomplete`. The training set is class-imbalanced, so accuracy can hide poor minority-class performance. **Macro-F1** is the primary metric: it averages per-class F1 with equal weight, penalizing models that win on the majority class while ignoring the minority class.

## Data Balancing (Phase 2)

The same model — TF-IDF + `LinearSVC` — is used across all three balancing strategies so any difference is attributable to the data balancing step. Validation: a single stratified 80/20 split (`random_state=42`). TF-IDF parameters: `ngram_range=(1,2)`, `min_df=2`, `sublinear_tf=True`.

### Methods compared

1. **Baseline:** no balancing.
2. **Random over-sampling (required):** duplicate minority-class rows with replacement until the class ratio is 1:1. Implemented in `perform_balancing(df, method='random')`.
3. **Cost-sensitive learning (advanced):** `LinearSVC(class_weight='balanced')`. The hinge-loss penalty for misclassifying the minority class is scaled inversely to its prevalence, which moves the decision boundary toward the majority class without changing the data.

### What "random over-sampling" does

Random over-sampling repeatedly samples (with replacement) from the minority class until both classes have the same row count. Because samples are exact copies, this does not introduce new information — it changes only the loss landscape that the optimizer sees, putting more weight on the minority decision region.

### What "Macro-F1" is

Macro-F1 averages the per-class F1 score with equal weight across classes. F1 itself is the harmonic mean of precision and recall, so a class with very low recall pulls the Macro-F1 down regardless of how many samples it has. This is exactly the property we want under class imbalance, where accuracy and weighted F1 can be high even when the minority class is essentially ignored.

### Results

| Method | Validation Macro-F1 |
|---|---:|
| Baseline TF-IDF + LinearSVC      | **0.7919** |
| Random Over-sampling             | 0.7777 |
| Cost-sensitive LinearSVC         | 0.7771 |

### Analysis — which method performed better and why

On this validation split, **the unbalanced baseline slightly outperformed both balancing methods**. Two plausible reasons:

- Random over-sampling injects exact duplicates of minority-class rows. The classifier sees the same TF-IDF vectors many times and can fit them tightly, but those duplicates carry no new linguistic information — so a random over-sampled training set can effectively *amplify* memorization of a few minority examples without improving generalization.
- Cost-sensitive learning shifts the LinearSVC decision boundary aggressively to favor the minority class. On this dataset the imbalance is moderate, so the boundary shift trades precision for recall on class 0 and ends up costing macro-F1.

This does **not** mean balancing is useless. It is a hypothesis worth testing on every imbalanced dataset, and the balancing comparison must be reported even when the baseline wins, because the comparison is what justifies *not* using a more complex method.

## Modeling & Enhancements (Phase 3)

### Methods implemented

- **Stratified 5-fold cross-validation** (replacing the single 80/20 split) for more reliable Macro-F1 estimates.
- **Hyperparameter sweep** over TF-IDF and the linear head, deliberately compact (~12 single configs):
  - word n-grams: `(1,2)`, `(1,3)`
  - character n-grams: `char_wb` `(3,5)`, `(4,6)`
  - `min_df=2`, `sublinear_tf=True`
  - `LinearSVC` `C ∈ {1, 2}`, `class_weight ∈ {None, 'balanced'}`
  - `LogisticRegression` `C ∈ {1, 2}`, `class_weight ∈ {None, 'balanced'}`
  - one config with random oversampling on the best word config for cross-check
- **Word + character ensemble.** Independently fit the best word and best character models, take each model's `decision_function`, **z-score each set of scores using train-fold statistics** (so the same recipe transfers from CV to test inference), and average them with weights from `{(0.3, 0.7), (0.5, 0.5), (0.7, 0.3)}`. Predict by thresholding the combined score at 0.

### Why these count as "advanced modeling"

The Phase 2 baseline is a single TF-IDF + LinearSVC with one validation split. Phase 3 strictly improves on it across four orthogonal axes:

1. **Validation reliability** — 5-fold Stratified CV averages over five splits, reducing the variance of the score we use to choose configs.
2. **Feature space** — character n-grams capture sub-word morphology and disfluency-marker patterns that whole-word tokens miss.
3. **Model heads** — comparing `LinearSVC` against `LogisticRegression` distinguishes hinge-loss vs. log-loss behaviour on the same features.
4. **Ensembling** — weighted score-level fusion of two complementary representations is a strict superset of using either alone.

### What "TF-IDF" and "SVM" are

- **TF-IDF (Term Frequency × Inverse Document Frequency):** a sparse, high-dimensional bag-of-tokens representation. Each token's weight in a document is its count (TF) re-scaled by how rare the token is across the corpus (IDF: `log(N / df_t)`). With `sublinear_tf=True`, TF is replaced by `1 + log(TF)` to dampen the effect of repetitive frequent tokens. We use both word-level and character-level (`char_wb`) tokens to capture different signals.
- **SVM (Support Vector Machine):** finds the linear hyperplane that maximizes the margin to the closest training points (the support vectors). For text, the `LinearSVC` variant solves the `hinge`-loss formulation directly in the high-dimensional sparse space without computing a kernel — which is exactly what TF-IDF features want.

### Results

Top single-model configurations from the 5-fold CV sweep:

| Config | Mean Macro-F1 | Std |
|---|---:|---:|
| **word(1,3) + LinearSVC C=1** | **0.8015** | 0.0256 |
| word(1,2) + LinearSVC C=1     | 0.8010 | — |
| char(3,5) + LinearSVC C=1     | 0.8001 | — |

Per-fold scores for the winner: `[0.7740, 0.7906, 0.8056, 0.8486, 0.7890]`.

Best ensemble configuration: `word * 0.3 + char * 0.7` with **Mean Macro-F1 = 0.7769**.

### Which method performed better and why

The best **single** word-level configuration (Macro-F1 = 0.8015) outperformed the best **ensemble** (0.7769). Two interpretations:

- **Word-level features already dominate.** The completion/non-completion cue in dialogue endpointing is largely lexical — sentence-final phrases, conversational fillers, and content-word density are well represented by word unigrams and bigrams/trigrams.
- **Char features add noise more than signal here.** The char-wb representation captures morphology and substring patterns that on this dataset overlap with the word-level signal, but also pull in spurious sub-token n-grams that hurt generalization when combined.

A weighted average that gives the worse component (char features) substantial weight (0.7) cannot exceed the better component on its own unless the two are well-calibrated and capture *different* errors. On this dataset they don't; on a different domain (e.g. heavy abbreviation, OOV-rich text) they might.

### Best Model Identification

- **Architecture:** TF-IDF (word, `ngram_range=(1, 3)`, `min_df=2`, `sublinear_tf=True`) + `LinearSVC(C=1.0, class_weight=None, random_state=42, max_iter=8000)`.
- **Validation:** Stratified 5-fold CV, mean Macro-F1 = 0.8015 ± 0.0256.
- **Submission:** trained on the **full** training set with the same configuration; prediction distribution on the test set is `label 1 = 308`, `label 0 = 192`.

# Limitations

- **Task 1 dataset is extremely small.** 16 trials × 4 classes leaves only 4 examples per class. Validation standard deviations are correspondingly large (top result is 0.5625 ± 0.1804). Differences in Macro-F1 of < 1 std should be treated as noise.
- **Training scores are not generalization scores.** Both the Task 1 full-fit (1.0/1.0) and Task 2 train fit (0.7457 Macro-F1) are sanity checks on the training distribution. They do not indicate test or leaderboard performance.
- **Local validation may not match Kaggle.** Distribution shift, sampling variance, and the small public split mean the local Macro-F1 numbers are best read as relative rankings of our own configs.
- **No official test labels were used for tuning** anywhere in the pipeline.
- **No external datasets and no pretrained models were used** for Part 1, per the spec.
- **Filter validity.** The 70–125 Hz band sits exactly at Nyquist for `sfreq=250 Hz`; the upper cutoff is internally clamped to 124.875 Hz to keep the Butterworth design valid. This is documented in `results_df` (`actual_high_hz`, `clamped_to_nyquist`).

- **Part 1 Task 1.** Best local CV configuration is **Design A (bandpass-only) on the 70–125 Hz band** with Macro-F1 = 0.5625 ± 0.1804. Design A beat Design B in 3 of 4 bands; per-trial z-scoring removes the very amplitude information that log-variance features depend on.
- **Part 1 Task 2.** A reproducible cross-subject pipeline is implemented end-to-end: multi-band log-variance features → StandardScaler → LogisticRegression with `class_weight='balanced'`, packaged in a self-describing `joblib` checkpoint. `inference.py` reconstructs the exact training-time preprocessing from the checkpoint, satisfying the required CLI and the submission CSV format.
- **Part 2.** Best local model is **word-level TF-IDF (1,3) + LinearSVC C=1** with 5-fold Stratified CV Macro-F1 = 0.8015 ± 0.0256. The word+char ensemble underperformed the best single model on this dataset.
